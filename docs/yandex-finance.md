# Яндекс Маркет: финансовый расчёт

Страница `/yandex-market/financier`, серверные маршруты `/api/agents/yandex-finance` и `/api/agents/yandex-finance-sync`. Доступ: неблокированные admin/senior_admin, как у существующего финансиста WB. Новые таблицы доступны только service_role; страницы и обработчики отдельно проверяют пользователя.

Данные берутся из двух отчётов XLSX: `united-marketplace-services` (dateFrom/dateTo, дата начисления) и `united-orders`. Старт и продолжение загрузки инициируются пользователем. Закрытие страницы приостанавливает опрос; кнопка «Загрузить / продолжить из ЯМ» продолжает сохранённое задание. Готовый кэш остаётся доступен во время новой загрузки. Незавершённые/ошибочные импорты никогда не используются для расчёта.

Ключ YANDEX_API_KEY_FULL используется только на сервере. Повторяющиеся одинаковые строки ключа убираются, разные ключи отклоняются. Business ID определяется по YANDEX_CAMPAIGN_ID. Отчёты формируются для всего кабинета, без фильтра FBY/FBS.

## Методика пользователя от 26.10.2026

Доход: лист «Транзакции по заказам и товарам», N × V. «Доставлен покупателю» плюс, статусы со словами «Возврат», «Отменён», «Невыкуп» минус, остальные ноль. N — «Ваша цена за шт.», V — «Передано в доставку». W не заменяет V. Пустое V оставляется неизвестным, сумма не включается, строка показана в предупреждениях. Это предварительный результат, пока не определено количество для этих строк.

Фильтр когорты: дата создания/оформления заказа включительно. Для услуг дополнительно проверяется дата начисления/оказания услуги. Если дата заказа отсутствует в листе услуги, используется дата из отчёта заказов по ID. Для средней мили, где колонка называется «Дата создания заказа или возврата», приоритет у известной даты исходного заказа. Неопределённая дата связанного заказа исключает строку с явной причиной. Услуги без заказа (хранение, подписки, реклама, приём излишков, транзит) фильтруются по дате услуги.

Маппинг 14 статей и букв столбцов — в `lib/yandex/finance.ts`. P программы лояльности и Z средней мили суммируются буквально, без дополнительного умножения на количество. AJ размещения до скидок, а не AX итоговой стоимости. Итог отличается от стандартной сводки ЯМ по заданной методике.

Общие расходы: показы, баннеры, транзит, обработка заказов на складе. Строки остальных статей без SKU тоже остаются в общих расходах, а не теряются.

Подписки распределяются по положительному чистому количеству выкупов SKU (доставленные минус отмены/возвраты/невыкупы). Отрицательные выкупы имеют вес 0. Метод наибольших остатков сохраняет точную сумму в копейках. При отсутствии положительных выкупов подписка остаётся общей статьёй.

Операционная прибыль = доход − расходы Маркета − себестоимость − ТК Маяк. Налоги не включены. Себестоимость = чистые выкупы × тариф себестоимости; ТК Маяк = все заказанные единицы × тариф ТК Маяк, включая отменённые и ещё не доставленные. Количество заказанных единиц берётся из v1/businesses/{businessId}/orders с полной пагинацией и окнами до 30 дней; пропущенное V отчёта доходов им не заменяется.

Тарифы редактируются в раскрытой строке артикула. История хранится по ЕНОТ и дате начала действия; для артикула без ЕНОТ применяется отдельный тариф. Сумма рассчитывается по тарифу на дату оформления каждого заказа. Ноль — известный бесплатный тариф, пустое значение — неизвестно. Изменения аудируются, конкурирующее сохранение возвращает 409. Новая дата не перезаписывает старые периоды. Начальные 411 тарифов импортированы из файла пользователя с 01.10.2026.

При отсутствующем тарифе или неполной загрузке количества заказов прибыль и зависимые показатели остаются неизвестными. Известная часть расходов не выдаётся за полный итог. В контрольной выгрузке отсутствуют тарифы для «Люстра 6 рожков L25092401-B» и «Топор1 AVA-1945».

Реклама = только «Буст продаж, оплата за продажи». ДРР = реклама / выручка. ROAS = операционная прибыль / абсолютная сумма рекламы, в процентах: это формула существующего финансиста Ozon. При нулевом знаменателе показатель неизвестен. Таблица повторяет порядок и названия Ozon без КМ, детали строки сверяются с прибылью. CSV за весь период использует десятичную запятую.

Остатки берутся из последней успешной синхронизации ЯМ и существующих складских источников; отсутствующие данные, включая склад кроссдокинга и прогнозы выручки в пути, отображаются прочерком.

```

```
