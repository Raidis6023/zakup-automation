# Интеграция с 1С v1

## Единая точка доступа для программистов 1С

**Метод:** GET  
**Путь:** /api/v1/1c/export  
**Формат:** application/json (UTF-8)  
**Передача:** HTTPS  
**Авторизация приложения:** Authorization: Bearer <ключ_интеграции>  
**Защита Vercel:** x-vercel-protection-bypass: <служебный_секрет_Vercel> (для защищённого проекта)

Это **один** входящий адрес. Параметр `dataset` определяет набор выгружаемых данных. Запись/изменение данных через этот интерфейс не поддерживается.

### 1. Доступные наборы данных

| dataset | Содержание | Обязательные параметры |
|---|---|---|
| catalog | Список доступных разделов и параметров | нет |
| products | Товары, артикулы и справочник ЕНОТ | нет |
| stocks | Остатки Аведэкс или ОХ ИП Бабушкиной | source |
| sales | Продажи по дням | marketplace, from, to |
| finance | Финансовая детализация | marketplace, from, to |

Параметры:

- `dataset=products`: можно добавить `enot=ABC123` для точного фильтра.
- `dataset=stocks`: `source=avedex` или `source=babushkina`. Необязательный `date=YYYY-MM-DD` выбирает дату снимка. Если не указан, отдаётся последний доступный снимок соответствующего источника.
- `dataset=sales`: `marketplace=ozon`, `wildberries` или `yandex_market`. Даты включительно. Для Wildberries в первой версии запрос строго за **один день** (`from=to`).
- `dataset=finance`: аналогичные значения `marketplace`, `from`, `to`. Для Яндекс Маркета в базе должен существовать **готовый отчёт ровно за этот период**, иначе код 409. Wildberries использует последний сохранённый финансовый кеш, фильтруемый по `rrDate`. Для Ozon данные идут из таблицы начислений.

### 2. Пагинация

Общая для всех наборов:

- `limit`: от 1 до 200, по умолчанию 100.
- `offset`: от 0, по умолчанию 0.
- `pagination.has_more`: есть ли ещё записи.
- `pagination.next_offset`: смещение следующей страницы или null.

**Алгоритм в 1С:** установить `offset=0`, запросить `limit=200`, обработать `data`, если `has_more=true`, запросить `next_offset` и повторять до конца. Результаты `data` не являются полной выгрузкой, если `has_more=true`. Повторная полная выгрузка может содержать обновлённые данные; в будущем для исторической дельта-синхронизации следует согласовать курсоры изменений/версии снимков.

Пример запроса номенклатуры:

```http
GET /api/v1/1c/export?dataset=products&limit=200&offset=0 HTTP/1.1
Host: <домен_сайта>
Authorization: Bearer <ключ_интеграции>
x-vercel-protection-bypass: <служебный_секрет_Vercel>
Accept: application/json
```

Пример запросов:

```text
/api/v1/1c/export?dataset=catalog
/api/v1/1c/export?dataset=products&enot=ABC123
/api/v1/1c/export?dataset=stocks&source=avedex
/api/v1/1c/export?dataset=stocks&source=babushkina&date=2026-10-23
/api/v1/1c/export?dataset=sales&marketplace=ozon&from=2026-10-01&to=2026-10-05
/api/v1/1c/export?dataset=sales&marketplace=wildberries&from=2026-10-12&to=2026-10-12
/api/v1/1c/export?dataset=finance&marketplace=yandex_market&from=2026-10-01&to=2026-10-26
```

Успешный ответ имеет формат:

```json
{
  "ok": true,
  "version": "1.0",
  "data": [],
  "pagination": {
    "limit": 200,
    "offset": 0,
    "has_more": false,
    "next_offset": null
  }
}
```

Данные `data` зависят от `dataset`. Ответ `catalog` возвращает метаданные без поля `data`.

Ошибки:

```json
{
  "ok": false,
  "version": "1.0",
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Неверный ключ авторизации"
  }
}
```

HTTP-коды:
- 400: неверные параметры, неизвестный `dataset`, некорректная дата.
- 401: ключ отсутствует или неверен.
- 403: у ключа нет доступа к выбранному разделу.
- 409: отсутствует готовый финансовый отчёт Яндекс Маркета за точный период.
- 422: объём продаж WB за конкретный день превышает установленный предел безопасной агрегации.
- 500: внутренняя ошибка чтения.
- 503: ключ интеграции не настроен на сервере.

### 3. Ограничения и трактовка данных

**ЕНОТ.** `products` возвращает одну строку на артикул, а не одну строку на ЕНОТ. Один код ЕНОТ может связываться с несколькими артикулами. В 1С первичный идентификатор записи — `product_id`; `enot` — общий товарный код для связей.

**Склады.** Аведэкс и ОХ Бабушкиной читаются из разных снимков. ОХ выбирается только по полному значению `owner_name` = «Бабушкина Ирина Алексеевна ИП». Другие владельцы ответственного хранения не выдаются. Поле `snapshot_date` показывает актуальность выгрузки; это не движение товаров в реальном времени. Остатки по SKU, складам, владельцам и датам не суммируются на сервере без явного указания.

**Продажи.** Ozon и Яндекс Маркет имеют собственные дневные таблицы. В WB продажи хранятся отдельными событиями; для одного дня группируются по `nm_id`, артикулу, штрихкоду и складу. Для WB связь с ЕНОТ в текущей базе не подтверждена, поэтому в ответе `enot: null`. Нельзя автоматически подставлять ЕНОТ по неточному совпадению названий. Количество событий WB не нужно приравнивать к бухгалтерским признанным продажам без согласованной методики.

**Финансы.** Это детализация финансовых строк маркетплейсов, а не бухгалтерская универсальная проводка. Поле `source` сохраняет значения исходного отчёта, включая внутренние статьи и знаки. Нельзя суммировать строки разных площадок без согласованной интерпретации. Для Яндекса выгружается полный готовый отчёт строго за указанный период.

**Период:** параметры `from` и `to` должны быть корректными календарными датами с интервалом не более 366 дней.

### 4. Настройка ключа интеграции (администратор)

Используется **отдельный секрет**, не ключ Supabase и не пользовательский пароль Workspace.

1. Сгенерировать случайный ключ длиной не менее 32 символов, например команда Python `import secrets; print(secrets.token_urlsafe(48))`.
2. Вычислить SHA-256 этого ключа, например `import hashlib; print(hashlib.sha256(KEY.encode()).hexdigest())`, где KEY — созданная строка.
3. В защищённых серверных переменных среды Vercel установить `ONE_C_API_KEY_SHA256` равным SHA-256 ключа. **Сам ключ в код/репозиторий и переменные `NEXT_PUBLIC_*` не записывать.**
4. Установить `ONE_C_API_SCOPES=finance,sales,products,stocks` (или более узкий список), затем выполнить деплой и проверить запрос `dataset=catalog`.
5. Передать исходный ключ программистам 1С **по отдельному защищённому каналу**, настроить его только в защищённом хранилище/настройках серверной 1С. В HTTP-запросах использовать `Authorization: Bearer <ключ>`. Вместе с ним необходим отдельный служебный секрет Vercel в заголовке `x-vercel-protection-bypass`, так как сайт защищён авторизацией Vercel на сетевом уровне.
6. Для отзыва доступа создать новый ключ и сменить хеш в переменных окружения, затем выполнить деплой. Служебный секрет Vercel отзывается и перевыпускается отдельно в разделе Deployment Protection проекта; секрет сам по себе не даёт права выгружать данные без Bearer-ключа.

В коде используется Node.js серверное сравнение хешей с постоянным временем; при отсутствии корректной переменной `ONE_C_API_KEY_SHA256` запросы блокируются кодом 503.

### 5. Проверки перед продуктивной передачей

- Отсутствующий/ложный ключ дают 401, а отсутствие серверной конфигурации — 503.
- Точный ключ даёт доступ только к разрешённым наборам.
- Запросить 200 + следующую страницу, проверить отсутствие пропусков и дублей.
- Проверить отдельные даты Аведэкс и ОХ Бабушкиной, отсутствие чужих владельцев.
- Сверить выборочный ЕНОТ и артикулы с карточками товара.
- Сверить финансовые строки и дневные продажи с отчётами площадок за те же периоды.
- Мониторить сборку и серверные ошибки. Передавать ключ 1С только после проверки фактического HTTPS-адреса деплоя.

**Статус:** метод размещён на основном домене `https://zakup-automation.vercel.app/api/v1/1c/export`. Для доступа необходимо передавать оба защищённых заголовка. Успешная сборка не заменяет проверку реального обмена из 1С.
