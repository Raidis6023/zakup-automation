# Workspace: общая система интерфейса

Цель: единые компоненты и оформление для всего рабочего пространства КПК МИА.
Не переносите интерфейс в один гигантский файл. Используйте общий каркас,
семантические дизайн-токены и небольшие переиспользуемые компоненты.

## Уже централизовано

- `app/WorkspaceShell.tsx`: общая оболочка, боковое меню, topbar и
  единственные хлебные крошки рядом с декоративными полосами.
- `app/ui/workspace-breadcrumb-routes.ts`: дерево известных маршрутов и
  автоматический безопасный fallback для будущих страниц.
- `app/ui/Breadcrumbs.tsx` и `Breadcrumbs.module.css`: вариант №5
  с вертикальной линией, кликабельные пункты, светлая/тёмная темы.
- `app/ui/PageHeader.tsx` и `PageHeader.module.css`: общие JSX-структура
  и геометрия заголовка. Сейчас подключены `/ozon`, `/wildberries`,
  `/yandex-market`, `/zakup`, `/sku-list`, `/ved`, `/stocks`,
  `/stock-import`, `/logistics-import`, `/responsible-storage-import`
  и `/ved-orders/[id]`. Сохраняются совместимые CSS-классы для
  плавного переноса локальных цветов и стилей.
- `app/MarketplaceFinancePanel.tsx`: общий блок «Финансовая аналитика»
  для трёх маркетплейсов, на базе `WorkspaceCollapsiblePanel`.
- `app/ui/tokens.css`: параметры интерфейса (размеры, отступы, радиусы,
  шрифты, фокус); единая точка изменения значений для компонентов,
  которые эти токены уже используют.
- `app/ui/Button.tsx`, `ButtonLink.tsx` и `Button.module.css`:
  общий стиль кнопок и ссылок, но ещё не все страницы мигрированы.

## Как создавать новые страницы

1. Рабочий маршрут размещайте внутри `app/`. Он автоматически получит
   оболочку Workspace и хлебные крошки от `WorkspaceShell`.
   Не добавляйте второй `Breadcrumbs` в `page.tsx`.
2. Если название или иерархия неочевидны, добавьте запись в
   `workspace-breadcrumb-routes.ts` с верным родительским URL.
   Иначе будет использован автоматический fallback по пути.
3. Для заголовка используйте `PageHeader` и подходящий согласованный
   вариант. При добавлении нового семейства страниц дополняйте
   общий компонент, не копируйте отдельную шапку.
4. Используйте `Button` и `ButtonLink` там, где стили уже мигрированы.
   Не маскируйте ссылки под обработчики событий у кнопок.
5. Контекстные действия («Обновить», «Загрузить», «Сформировать») размещайте
   в функциональных плашках, а не рядом с декоративными полосами.

## Что пока НЕ унифицировано

- HTML-таблицы Ozon/WB и CSS Grid Яндекс имеют разные структуры; базовые
  размеры шрифтов и отступы теперь берутся из общего набора токенов.
- Карточки, секции, раскрывающиеся плашки и наследованные кнопки теперь
  используют общие геометрические токены, не меняя фирменные цвета.
- Специализированные таблицы, карточки и вспомогательные панели
  всё ещё используют частные CSS-классы. PageHeader сам по себе
  пока не унифицирует их оформление.
- Часть кнопок на старых страницах.

Изменение компонента влияет на **подключённые** страницы. Оно не обязано
автоматически затрагивать разметку, которая ещё не использует общую систему.

## Регрессионная проверка при каждом переносе

Проверяйте светлую/тёмную темы, 1920/1366/1050/650 px, вертикальное
положение заголовка, отсутствие перекрытия декоративных полос, переходы
хлебных крошек, keyboard focus, маршруты действий и состояние таблиц.
Затем проводите сборку Next.js/TypeScript и проверяйте Vercel Preview.
Успешная компиляция **не заменяет** визуальную проверку приватного сайта.

## Пакетные изменения и стоимость Vercel

Собирайте и проверяйте файлы пакета до публикации ветки. Для публикации
создавайте один Git tree/commit для всех файлов. После одной проверки
preview объединяйте один PR с main, чтобы получать одну production-сборку.
Успешный build не заменяет визуальную проверку закрытых страниц.

## Геометрия карточек, плашек и таблиц

`app/ui/tokens.css` теперь содержит `--ui-surface-*` для секций и карточек,
`--ui-panel-*` для плашек и иконок, `--ui-table-*` для базовой геометрии
таблиц Ozon, WB и Яндекса, а `--ui-control-*` управляют кнопками.
Начальные значения соответствуют текущему виду. Меняя токены, проверяйте
все подключённые разделы, тёмную тему и мобильную ширину. Не объединяйте
разметку таблиц до отдельного аудита сортировки и функциональности.

## Яндекс FBY: общие раскрывающиеся плашки

Проверка доступности SKU и мультипоставка Яндекса переведены на `WorkspaceCollapsiblePanel`,
как другие функциональные плашки. Новые необязательные параметры `eyebrow`,
`wrapSubtitle`, `onAction`, `actionDisabled` поддерживают подпись, длинное описание
и отдельную кнопку справа. При нажатии на неё плашка не сворачивается.
Все таблицы и действия внутри скрываются вместе с телом; загрузка/расчёт
управляются прежними клиентскими состояниями и не переписывались.

## Таблицы привязки ЕНОТ, Ozon / WB / Яндекс

Общие правила расположены в `app/ui/enot-table.css`, который загружается
из корневого `app/layout.tsx`: оформление заголовков и строк, рамок,
ввода master_code и кнопок привязки. Различающиеся поля, размеры колонок,
состояния ошибок и поведение остались в CSS конкретных маркетплейсов.
Токены `--ui-enot-*` теперь задают минимальную ширину, высоту полей,
радиусы. Логика создания и сопоставления ЕНОТ остаётся в трёх отдельных
клиентских компонентах: унификация CSS не означает объединения логики.

## Карточки показателей закупа и ВЭД

Повторяющиеся интервалы карточек, размер иконки закупа/ВЭД и сетка KPI
используют `--ui-metric-*` в `app/ui/tokens.css`. Индивидуальные размеры
и цвета отдельных карточек оставлены без изменений.

## Централизованные структуры страниц (без новых файлов CSS)

Совпадающие правила заголовков, карточек показателей, статусов, блока
синхронизации, таблиц продаж по дням, информационных карточек и секций
товаров вынесены из CSS Ozon, Wildberries, Яндекса, Закупа и ВЭД
в существующий `app/workspace-reference-components.css`.

Старые имена классов поддерживаются как совместимые селекторы. **Для новых
страниц** используйте общие классы `ws-summary-grid`, `ws-summary-card`,
`ws-summary-icon`, `ws-summary-copy`, `ws-status-badge`,
`ws-status-dot`, `ws-info-card`, `ws-info-list`,
`ws-daily-table`, `ws-products-section`. Не копируйте их правила
в отдельный CSS страницы. Общая геометрия управляется `app/ui/tokens.css`.

Цвета маркетплейсов, уникальные таблицы, отдельные виджеты и логика
расчётов остаются самостоятельными. Унификация не означает, что все
маршруты уже полностью перешли на общие элементы.

### Правило для следующих изменений

Сначала проверьте существующие токены и общие компоненты, затем
добавляйте семантический вариант в уже существующий общий файл, только
если действительно нужен. Запрещено дублировать один и тот же
структурный стиль в CSS разных страниц. Для проверки сравнивайте базовые
правила Ozon/WB/Яндекс/Закуп/ВЭД и проверяйте Preview одной пачкой.

## Единое начальное состояние плашек

- `WorkspaceCollapsiblePanel` на всех страницах по умолчанию закрыт. Пользователь раскрывает его нажатием, все вложенные таблицы и формы остаются в теле панели.
- Разделы «Данные по товарам» Ozon/WB/Яндекс/Закуп тоже всегда закрыты при входе: ранее сохранённые в браузере состояния больше не считываются и не записываются.
- Адресный параметр `focusStockDays` сохраняет поиск и подсветку нужного артикула при последующем ручном раскрытии таблицы, но не раскрывает раздел автоматически.
- `MarketplaceSuppliesPanel` уже был закрыт по умолчанию; раскрытия отдельных строк внутри таблиц и HTML `details` остаются закрытыми как прежде.
- Новые функциональные секции необходимо создавать через общий `WorkspaceCollapsiblePanel` без собственного сохранения состояния раскрытия.
