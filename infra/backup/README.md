# ПАНДА: подготовка защищённого резервирования

Статус: подготовленные сценарии. **Рабочий сервер и резервное хранилище пока не подключены.**

## Что сохраняем вместе

- PostgreSQL 17: полная логическая копия (включая Auth, метаданные фотографий, Vault, функции) и роли.
- Содержимое локального хранилища фотографий и документов Supabase.
- Корневой ключ шифрования pgsodium_root.key из Docker-хранилища db-config.
- Настройки Supabase, ПАНДЫ и секреты её служебных подключений.

Все файлы загружаются в зашифрованный архив Restic **на другое физическое устройство / удалённый сервер**. Настройки такого устройства в GitHub не размещаем. Пароль Restic нужно сохранить отдельно от основного сервера: без него архив не восстановить.

## Самое важное правило

Сценарий backup.sh предназначен для согласованной полной резервной копии **при остановленной записи**. Перед ним отключаются сайт, фоновый планировщик, прямые интеграции, автоматические SQL-задания и любые процессы, способные сохранять файлы. Ручной параметр PANDA_WRITES_PAUSED=YES является подтверждением оператора, **не автоматической защитой**. Оператор отвечает за действительную остановку всех записей.

Ежедневные копии без простоя пока не подготовлены. Запускать эту программу автоматически каждые сутки нельзя.

## Необходимые параметры сервера

- PANDA_SUPABASE_DIR: абсолютный путь до папки официального Supabase (с volumes/storage).
- PANDA_APP_DIR: абсолютный путь до кода ПАНДЫ, где находится .env.docker.
- PANDA_SECRETS_DIR: каталог с файлами supabase-secret-key и cron-secret.
- PANDA_BACKUP_STAGE_DIR: отдельная защищённая папка под временную копию (должна вместить архив БД и фотографий).
- RESTIC_REPOSITORY: защищённое ВНЕШНЕЕ хранилище Restic, например SFTP/S3.
- RESTIC_PASSWORD_FILE: файл с паролем шифрования, доступный только root.
- PANDA_WRITES_PAUSED=YES: подтверждение остановки всех записей.

Сценарий требует root, Docker, restic и стандартные утилиты Linux. Ключи не передаются аргументами команд и не выводятся в журнал. Временные файлы с чувствительной информацией на диске удаляются при завершении. Удаление временных файлов на SSD **не равно гарантированному физическому стиранию**, поэтому диск сервера должен быть зашифрован.

Пример для сисадмина, **только после настройки путей, внешнего хранилища и остановки записей**:

~~~bash
sudo env PANDA_WRITES_PAUSED=YES \
  PANDA_SUPABASE_DIR=/srv/panda/supabase \
  PANDA_APP_DIR=/srv/panda/app \
  PANDA_SECRETS_DIR=/srv/panda/secrets \
  PANDA_BACKUP_STAGE_DIR=/srv/panda/backup-staging \
  RESTIC_REPOSITORY=sftp:backup-user@backup-host:/panda \
  RESTIC_PASSWORD_FILE=/root/.config/panda/restic-password \
  bash /srv/panda/app/infra/backup/backup.sh
~~~

backup-host указан для примера. Конкретный внешний адрес ещё неизвестен. Внешние VPN и туннели не нужны.

## Восстановление в аварийной ситуации

1. Подготовить **другой чистый тестовый сервер**, не изменять действующую ПАНДУ.
2. Скачать нужный снимок из Restic, проверить SHA256SUMS и наличие postgres.dump, storage.tar, postgres-globals.sql, host-config, panda-secrets, db-config/pgsodium_root.key.
3. Вернуть ключ db-config **до** запуска новой базы, иначе Vault может стать нечитаемым.
4. Развернуть совпадающую официальную версию Supabase 17. Восстановить роли и схему/данные PostgreSQL, разрешить конфликты внутренних ролей с уже установленным Supabase. Этот шаг ещё **не автоматизирован**, и старые SQL-задания не должны запускаться автоматически.
5. Вернуть файлы в локальное хранилище, проверить наличие и чтение фотографий.
6. Проверить вход пользователей, права доступа, расчёты, показатели, рекламу и функции ВЭД.
7. Отдельно восстановить систему HTTPS и сертификаты, если они были на другом хосте. Эта первая копия не содержит сертификатов веб-сервера.
8. Только после успешного восстановления включать фоновую работу.

**Ограничение:** создание архивов и извлечение проверяются отдельно на временном Docker. Полный пробный перенос настоящей базы пока не выполнялся. Не называть это готовым аварийным восстановлением.

## После проверки

Прежде чем выбирать расписание, нужно согласовать объём копий, доступное место, другой физический носитель, срок хранения, резервные копии ключей и проверку восстановления по расписанию. Автоматическое удаление старых снимков до успешной полной проверки восстановления запрещено.
